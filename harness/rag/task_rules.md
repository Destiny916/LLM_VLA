# RAG 任务规则

> 用途：定义任务拆分、子任务、任务级复位和任务队列编辑规则。

## 任务与子任务

- 一个用户输入可以被拆成多个任务。
- 一个任务可以包含多个子任务。
- 子任务由一个或多个动作 token 组成。
- 任务是复位边界，动作不是复位边界。

## 任务级复位

旧规则“每个 left/right 后必须 reset”废弃。

新规则：

- 动作之间不强制复位。
- 每个任务完成后必须执行一次 `reset`。
- 全部任务完成后进入 `hold_reset`。
- 如果 LLM 输出的任务为空，系统应进入 `hold_reset`，不能关闭仿真。

## 任务拆分建议

以下表达通常表示同一任务内的多个子任务：

- “上举后左转”
- “放下后右转”
- “保持上举再右转”

以下表达通常可以拆成多个任务：

- “然后”
- “接着做另一个”
- “完成后再”
- 用户显式说“任务一”“任务二”

## 任务操作

LLM 输出的任务操作只允许：

```text
add
stop
remove
modify
continue
```

规则：

- `add`：新增任务到队列。
- `stop`：停止当前任务或任务队列，不关闭仿真。
- `remove`：删除尚未执行的任务。
- `modify`：修改已有任务。
- `continue`：继续当前未完成任务或按用户补充继续规划。

## 任务队列安全

- `remove` 和 `modify` 必须引用存在的任务。
- 如果引用不明确，CLI 应要求 LLM 输出可见摘要并拒绝执行，或询问用户澄清。
- 任何任务操作都不能绕过本地校验。
